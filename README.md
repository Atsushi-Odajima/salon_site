# hair & spa 凪 — 美容室ホームページ制作見本

> **これは制作見本です。** 店舗・スタッフ・予約はすべて架空です。実際の予約・送信・通知は行われません。

ミツモア・くらしのマーケット等で「ホームページ作成」をご検討中の美容室オーナー様に、完成イメージを体験していただくための見本サイトです。

- 公開URL：<https://salon-site-nagi.vercel.app/>
  - トップ：`/`　予約体験：`/reserve/`　店側の予約管理：`/admin/`
- 管理画面の体験用パスワード：**`demo`**（画面にも表示しています。体験用の入口であり、本番の認証機能ではありません）

## 見どころ

1. **料金シミュレーター** — 基本メニューを1つ＋オプションを選ぶと、税込合計と所要時間がその場で分かり、そのまま予約へ進めます（例：カット＋カラー 11,000円／120分 ＋ トリートメント 2,200円／30分 ＝ 13,200円／150分）
2. **スタッフ紹介から指名予約** — 担当者の得意なスタイル・接客で大切にしていること・指名料を見て、その人を指名したまま予約できます（選んだメニューも引き継ぎ）
3. **空いている時間だけ選べる予約** — 勤務時間・休憩・既存予約・個室スパルームの空きを見て、施術全体が収まる枠だけを表示
4. **店側の予約管理** — PC はスタッフ別タイムライン、スマホは日付・スタッフ切り替えの一覧。確定／来店済み／キャンセルを変更可能
5. スタイル比較スライダー（ドラッグ・ボタン・矢印キー）、長さ・雰囲気で絞り込めるギャラリー、控えめな光と影の演出

## 技術構成

- **Vite + TypeScript**（フレームワークなし）の3ページ構成。表示が速く、古いスマホでも軽いことを優先しました。各ページは静的HTMLとして出力されるため、`/reserve/`・`/admin/` を直接開いたり再読み込みしたりしても表示できます
- スタイルは素のCSS（`src/styles/base.css` の CSS変数でデザイントークンを管理）
- GSAP（Flip）はギャラリーの並び替え時だけ遅延読み込み。Lenis は使っていません
- アイコン：Iconoir（MIT）＋同じ線幅の自作アイコン。ブランドロゴ：Simple Icons（CC0）

### 主なファイル

| ファイル | 役割 |
|---|---|
| `src/lib/menu.ts` | メニュー・料金・所要時間と計算処理 `quote()`（料金表・シミュレーター・予約・管理画面で共通） |
| `src/lib/staff.ts` | スタッフ・勤務・休憩・対応メニュー・指名料 |
| `src/lib/schedule.ts` | 営業日・定休日・空き枠の判定 |
| `src/lib/store.ts` | 予約データの保存（デモは localStorage）。**保存先の差し替えはこのファイルだけ** |
| `src/pages/*.ts` | 各ページの処理 |
| `partials/*.html` | ヘッダー・フッター等の共通部品（ビルド時に差し込み） |

## 予約の判定ルール（簡略モデル）

- 日本時間で当日〜90日先。月曜日と第3火曜日（その月の15〜21日にあたる火曜日）は定休日。過去日・当日の経過済み時刻は選べません
- 開始は9:30から30分刻み。施術全体が19:00まで、かつ担当美容師の勤務時間内に収まる枠だけを表示
- 所要時間には準備・片付けを含みます（別のバッファは加算しません）。終了時刻と次の開始時刻が同じ場合は重複としません
- **1人の美容師が開始から終了まで担当**します（カラー放置中の掛け持ちや途中交代は扱いません）
- 指名なしの場合も、施術全体を1人で担当できる美容師がいる枠だけを表示し、固定の順番（森下→水野）で割り当てます。複数スタッフの空き時間の継ぎ足しはしません。指名なしでは指名料は0円です
- **個室スパルーム（1室）**：ヘッドスパを含む予約は、その予約の開始から終了まで個室を確保する簡略モデルです。担当が別でも、ヘッドスパを含む予約同士は重複できません
- セット面4席・シャンプー台2台の工程別管理は扱いません（同時に担当する美容師が最大2名のため）
- 保存直前にも空きを再確認し、同じ操作（二重クリック）で予約が重複登録されないようにしています
- 保存する予約には、予約時点のメニュー名・料金・指名料・所要時間を記録します（後から料金を変えても過去の予約は書き換わりません）
- キャンセルした予約は空き枠を塞ぎません。キャンセルから確定へ戻すときは重複を再確認します

## デモデータについて

- 予約はお使いのブラウザ（localStorage）にだけ保存されます。別端末との共有や店舗への通知はありません
- 初回表示時に、今日から4週間分のデモ予約（満席の日を含む）を日付から決まる固定パターンで作成します
- 管理画面の「デモデータを初期状態に戻す」で、この見本が保存したデータ（`nagi-demo:` で始まるキー）だけを初期化します

## 本番運用に向けて（このままでは本番になりません）

`src/lib/store.ts` の `repo` を Supabase などの実装に差し替えれば保存先は変えられますが、**それだけで本番の予約システムになるわけではありません**。少なくとも次の対応が別途必要です。

| 項目 | 必要な対応の例 |
|---|---|
| 認証・権限管理 | 管理画面の本物のログイン（Supabase Auth 等）、スタッフ・オーナーの権限、Row Level Security |
| 同時予約の競合防止 | DB 側の排他制約（時間帯の重複禁止）やトランザクション。ブラウザ側の確認だけでは同時アクセスを防げません |
| 通知 | お客様への予約確認メール・SMS、店舗への新着通知、前日リマインド |
| 外部連携 | ホットペッパービューティー・LINE 等との空き枠同期は本見本では行っていません（リンク設置のみ）。連携には各サービスの提供する仕組みと契約が必要です |
| 個人情報 | プライバシーポリシー、保存期間、SSL、アクセス制限 |
| 運用 | 臨時休業・シフト変更の管理画面、キャンセルポリシー、バックアップ |
